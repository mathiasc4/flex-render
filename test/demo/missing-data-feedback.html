What this demo shows

  • The custom demo TileSource returns normal canvas tiles for most coordinates.
  • Selected coordinates return deterministic failure payloads for specific diagnostic reasons.
  • invalid-data exercises bitmap decode/preparation failure handling.
  • tainted-data exercises the drawer-side canvas taint preflight path.
  • unsupported-data exercises structured unsupported payload handling.
  • FlexRenderer should render missing-data feedback as a warning glyph and border inside the affected tile.

Checks

  1. With diagnostics enabled, affected tiles should show the warning marker.
  2. With diagnostics disabled, affected tiles should not render warning markers.
  3. Changing the scenario should produce deterministic affected tiles.
  4. The renderer state readout should preserve the expected diagnostic reason exactly.
  5. The shader layer controls should still behave normally.

The demo taint case is synthetic and local. It simulates canvas readback failure so the diagnostic path can be tested without depending on external CORS headers.
